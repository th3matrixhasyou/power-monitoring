# Мониторинг инфраструктуры (энэргопотребление).

Контейнеризованный стек мониторинга инфраструктуры, построенный в соответствии с принципами **Infrastructure as Code (IaC)**.

Проект предназначен для централизованного мониторинга доступности операционных систем, состояния серверного оборудования и энергопотребления серверов и рабочих станций

## 🏗 Архитектура

Стек мониторинга состоит из следующих компонентов:

| Компонент | Описание |
|---|---|
| **Prometheus** | Собирает, хранит и обрабатывает данные временных рядов (TSDB). |
| **Blackbox Exporter** | Проверяет доступность операционных систем с помощью ICMP. |
| **IPMI Exporter** | Собирает аппаратные метрики с серверов Huawei и Lenovo через IPMI 2.0 (LAN 2.0). |
| **Node Exporter** | Собирает системные метрики и считывает пользовательские метрики через `textfile_collector`. |
| **Custom Power Collector** | Bash-скрипт `get_power.sh` для сбора данных об энергопотреблении через DCMI и IPMI SDR. |
| **Grafana** | Обеспечивает визуализацию метрик и мониторинг состояния инфраструктуры. |

Все компоненты развертываются в Docker-контейнерах с использованием Docker Compose.

Конфигурации Prometheus, Grafana и других компонентов хранятся в Git-репозитории. Дашборды Grafana управляются через JSON Provisioning.

## 🔌 Мониторинг энергопотребления (IPMI / DCMI)

Из-за различий в реализациях BMC у разных производителей оборудования (Huawei TaiShan, Lenovo XCC и др.) стандартный IPMI Exporter не всегда предоставляет точные показания энергопотребления в Ваттах.

В частности, некоторые реализации могут возвращать нулевые значения или показания отдельных резервных блоков питания, которые не отражают фактическое энергопотребление всей системы.

Для решения этой проблемы реализован собственный механизм сбора метрик — `get_power.sh`.

Скрипт использует гибридный алгоритм опроса, автоматически выбирая подходящий метод получения данных.

### Алгоритм сбора данных

**1. DCMI (Data Center Manageability Interface)**

Сначала скрипт выполняет следующую команду:

```bash
ipmitool dcmi power reading
```

DCMI предоставляет единое мгновенное значение энергопотребления всей системы (`Instantaneous power reading`).

Это предпочтительный метод для серверов, поддерживающих соответствующую реализацию DCMI.

**2. IPMI SDR (Sensor Data Record)**

Если DCMI не поддерживается, не возвращает корректные данные или сообщает о нулевом энергопотреблении, скрипт переключается на альтернативный метод:

```bash
ipmitool sdr list full
```

После этого выполняются следующие операции:

- Получение полного списка аппаратных сенсоров.
- Поиск сенсоров, связанных с энергопотреблением.
- Фильтрация нулевых значений.
- Выбор корректных показаний для формирования метрик.

Такой подход позволяет учитывать различия прошивок оборудования разных производителей и получать более точные данные об энергопотреблении.

### Передача метрик в Prometheus

Результаты, сформированные `get_power.sh`, записываются в файл:

```text
textfile_data/ipmi_power.prom
```

Node Exporter считывает этот файл с помощью `textfile_collector` и передает собранные метрики в Prometheus.

Это позволяет осуществлять мониторинг энергопотребления независимо от основного IPMI Exporter.

## ➕ Добавление новых серверов

Добавление нового оборудования выполняется через конфигурацию Prometheus.

Независимо от производителя сервера и поддерживаемого метода сбора данных об энергопотреблении (DCMI или IPMI SDR), процедура добавления сервера остается одинаковой.

**Протокол сбора данных об энергопотреблении автоматически выбирается скриптом `get_power.sh`.**

### Шаг 1. Добавление целей мониторинга

Откройте следующий файл:

```text
prometheus/prometheus.yml
```

Для каждого нового сервера необходимо добавить две цели мониторинга:

- В `icmp_ping_servers` — IP-адрес операционной системы.
- В `ipmi_servers` — IP-адрес интерфейса iBMC.

Пример:

**ICMP — проверка доступности ОС:**

```yaml
- targets:
    - '192.168.0.255'
  labels:
    hostname: 'g10-newserver'
    rack: 'g10'
    team: 'Cloud'
```

**IPMI — мониторинг аппаратных компонентов через iBMC:**

```yaml
- targets:
    - '192.168.0.254'
  labels:
    __param_module: 'ibmc_192_168_0_254'
    hostname: 'g10-newserver'
    rack: 'g10'
    team: 'Cloud'
```

> **Важно:** Соблюдайте обязательную структуру меток: `hostname`, `rack`, `team` и `__param_module`. Эти метки используются конфигурацией мониторинга и скриптом `get_power.sh` для идентификации оборудования и группировки метрик по стойкам в Grafana.

### Шаг 2. Добавление учетных данных iBMC

Добавьте учетные данные нового сервера в конфигурацию IPMI Exporter.

Для этого расшифруйте `ipmi.yml.enc` в оперативную память (RAM), внесите необходимые изменения и снова зашифруйте файл.

Подробные инструкции приведены в разделе [Управление безопасностью](#-управление-безопасностью).

### Шаг 3. Применение изменений

После обновления конфигурации выполните:

```bash
./deploy.sh
```

Скрипт подготовит конфигурацию и применит изменения к контейнерам.

## 🤖 Автоматизированное управление хостами (manage_host.sh)

Во избежание ошибок при ручном редактировании YAML-файлов и работе с OpenSSL, в проект добавлен интерактивный скрипт `manage_host.sh`. Он полностью заменяет рутинные шаги из раздела «Добавление новых серверов».

### Возможности скрипта:
- **Интерактивный ввод:** Запрашивает IP-адреса, hostname, команду (team) и предоставляет выбор стойки (rack) из автоматически собранного списка.
- **Безопасная обработка паролей:** Запрашивает пароль от iBMC с подтверждением, самостоятельно проводит расшифровку `ipmi.yml.enc`, добавляет учетные данные и зашифровывает файл обратно, не оставляя следов на диске.
- **Защита от синтаксических ошибок:** Точно соблюдает отступы при добавлении таргетов в `prometheus.yml`.
- **Умное удаление:** Позволяет корректно вырезать хосты из конфигурации по их `hostname`.
- **Горячее применение:** После добавления или удаления скрипт автоматически перезапускает необходимые контейнеры (`prometheus` и `ipmi-exporter`) для мгновенного отображения изменений в Grafana.

Для запуска скрипта выполните (требуются права для работы с Docker):

```bash
sudo ./manage_host.sh
```

## 🚀 Развертывание

Для развертывания стека на новом хосте выполните следующие шаги:

**1. Клонирование репозитория:**

```bash
git clone <repository-url>
cd <repository-directory>
```

**2. Подготовка скрипта развертывания:**

```bash
chmod +x deploy.sh
```

**3. Запуск развертывания:**

```bash
./deploy.sh
```

Во время выполнения скрипт запросит мастер-пароль для расшифровки конфигурации iBMC.

Расшифрованные учетные данные передаются при подготовке Docker Secrets без создания постоянного файла с открытым текстом на SSD.

Помимо базового запуска контейнеров, скрипт `deploy.sh` автоматически:
- Настраивает задачу в `cron` для выполнения `get_power.sh` каждую минуту (обеспечивая сбор энергопотребления).
- Ожидает полной готовности Grafana и автоматически создает пользователя `monitoring` (только для просмотра) через REST API.

## 🔐 Управление безопасностью

### Защита учетных данных iBMC

Учетные данные защищены шифрованием OpenSSL AES-256-CBC с использованием PBKDF2.

Открытый файл `ipmi.yml` не хранится в Git-репозитории и не должен сохраняться на постоянных носителях.

Зашифрованная конфигурация находится по следующему пути:

```text
ipmi/ipmi.yml.enc
```

Для редактирования конфигурации (в случае отказа от использования `manage_host.sh`) используется временное хранилище в оперативной памяти Linux — `/dev/shm`.

### 1. Просмотр конфигурации

Чтобы просмотреть содержимое зашифрованного файла без сохранения расшифрованной версии на диск, выполните:

```bash
openssl enc -aes-256-cbc -d -salt -pbkdf2 \
  -in ipmi/ipmi.yml.enc
```

OpenSSL запросит мастер-пароль и выведет расшифрованное содержимое непосредственно в терминал.

### 2. Редактирование учетных данных

**Шаг А. Расшифровка в оперативную память (RAM)**

```bash
openssl enc -aes-256-cbc -d -salt -pbkdf2 \
  -in ipmi/ipmi.yml.enc \
  -out /dev/shm/ipmi-edit.yml
```

Введите мастер-пароль.

**Шаг Б. Редактирование конфигурации**

```bash
nano /dev/shm/ipmi-edit.yml
```

Добавьте новый модуль iBMC или обновите существующие учетные данные.

**Шаг В. Повторное шифрование обновленного файла и сохранение на SSD**

```bash
openssl enc -aes-256-cbc -salt -pbkdf2 \
  -in /dev/shm/ipmi-edit.yml \
  -out ipmi/ipmi.yml.enc
```

(Введите и подтвердите мастер-пароль.)

**Шаг Г. Уничтожение файла с открытым текстом из RAM (КРИТИЧЕСКИ ВАЖНО)**

```bash
rm -f /dev/shm/ipmi-edit.yml
```

После завершения процедуры:

1. Убедитесь, что зашифрованный файл `ipmi.yml.enc` обновлен.
​2. Зафиксируйте изменения в Git (commit).
3. Запустите `./deploy.sh`, чтобы применить обновленную конфигурацию.

> **Важно:** `/dev/shm` использует временную файловую систему, расположенную в оперативной памяти. Это снижает риск сохранения учетных данных в открытом виде на SSD, но не гарантирует полного отсутствия следов в файле подкачки (swap), дампах памяти или системных журналах. Для дополнительной защиты рекомендуется отключить swap или использовать зашифрованный swap, а также ограничить доступ к процессам мониторинга.

## 📊 Управление дашбордами Grafana

Дашборды Grafana управляются через JSON Provisioning и хранятся в Git-репозитории.

Основной файл дашборда:

```text
grafana/dashboards_json/nlrc_custom.json
```

Изменения необходимо вносить через Git, чтобы обеспечить сохранность конфигурации и возможность восстановления дашбордов после пересоздания контейнера.

### Процедура обновления дашборда

**1.** Откройте необходимый дашборд в веб-интерфейсе Grafana.

**2.** Внесите необходимые изменения.

**3.** Экспортируйте обновленный дашборд в формате JSON.

**4.** Замените содержимое файла:

```text
grafana/dashboards_json/nlrc_custom.json
```

**5.** Зафиксируйте изменения в Git:

```bash
git add grafana/dashboards_json/nlrc_custom.json
git commit -m "Update Grafana dashboard"
git push
```

Grafana автоматически обнаруживает изменения JSON-файлов через настроенный механизм Provisioning с интервалом проверки 10 секунд.

> **Важно:** Не используйте веб-интерфейс Grafana в качестве постоянного хранилища конфигурации. Git-репозиторий является единственным источником истины (Single Source of Truth).
